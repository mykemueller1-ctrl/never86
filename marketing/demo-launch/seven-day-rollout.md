# The first seven days

Start with one visible product example and ten observed operator sessions. The initial target is learning whether operators can finish one useful check. It is not 100,000 signups or an unmeasured reach promise. Use organic posts first; no ad budget was supplied and no spend is authorized by this plan.

## Who this first demo is for

Primary: an owner or general manager at an independent restaurant who buys food, covers shifts, and checks the numbers. Secondary: a kitchen manager or front of house manager with the same operational problem and permission to use the needed records. Software buyers, large chains and AI enthusiasts are not substitutes for these users in the first ten tests.

The first promise is small: understand one cost question and the next action. The bigger product offer is one location and one seat free, with paid manager seats. Connectors and live seats are later release claims until they work.

| 6 | Publish a specific product correction only if it was built and verified. Otherwise use the handoff copy below. | Builder supplies proof. Myke publishes. | Repeat the affected test. Do not count a content change as a product fix. |

This cadence is an experiment. Choose publishing times when Myke can read replies. There is no verified universal best hour or guaranteed benefit from hiding the link in a comment. Put the demo link where a reader can use it.

## Production work that agents can do at scale

Keep a single record for each asset: source, claim, draft, approved copy, actual build version, image, link, channel and results. A useful workflow is research → choose one operator problem → write → check claims → capture the verified feature → review → publish → measure → fix the product.

| Role | Deliverable | Done when |
| --- | --- | --- |
| Research agent | A short operator problem with public source links and a clear distinction between a complaint and an established fact. | No private source or copied review becomes a testimonial. |
| Product evidence agent | One reproducible input, result and calculation. | The deployed demo gives the stated result and keeps its sample label. |
| Copy agent | One founder draft and a shorter channel adaptation. | Costs and the operator’s question lead. No invented results or jargon. |
| Design agent | One readable screen crop and a short captioned walkthrough. | Numbers and labels are readable on a phone. |
| Review agent | Claim, brand, accessibility and link checks. | Every public claim matches the release being shown. |
| Reporting agent | Channel results and product completion data, with missing metrics labeled. | It distinguishes viewers, visitors, sample completions and live customers. |
| Myke | The founder’s final wording and publication through the native service or an approved integration. | The published asset and link match the reviewed copy. |

The agents produce drafts and reports. This package creates no recurring jobs and sends no messages. LinkedIn prohibits unauthorized automation and artificial engagement. X disallows website scripting for automation and requires prior written approval for AI reply bots. Build distribution around useful posts, relevant human replies and opt in followup. [LinkedIn agreement](https://www.linkedin.com/legal/user-agreement), [X automation rules](https://help.x.com/en/rules-and-policies/x-automation)

If a partner is paid or receives a benefit to endorse the product, record and disclose that relationship clearly. Do not present a paid demo as an independent customer result. ## Measure the complete path

For the first tests, use the blank scorecard. Ask each participant to pick the job closest to their work. Start a timer at the sample entry screen. Let them proceed without coaching. A finished check means they can identify the relevant sample inputs, explain the result, and select a sensible next action. Merely opening a result does not count.

Proposed events for the eventual instrumented demo: `demo_started`, `job_selected`, `source_opened`, `check_completed`, `handoff_drafted`, `feedback_submitted`. These are proposed event names, not a claim that analytics is wired. Record timing manually until verified instrumentation exists. Never put receipt contents, employee names or pay rates into marketing analytics.

Use `utm_source=linkedin` or `utm_source=x`, `utm_medium=organic_social`, `utm_campaign=sample_demo`, and `utm_content=founder_video`, `invoice`, `labor`, `pour`, or `handoff` when the URL builder and analytics preserve these parameters. Traffic labels alone do not create measurement. Keep an unmodified copy of the final URL for verification.

Report raw counts: unique sample visitors where measured, starts, completed checks, completed checks within 600 seconds, source comprehension, and agreed followups. Report median completion time only for completions alongside the failure count. Do not silently remove incomplete sessions. LinkedIn’s own post analytics include reach, link visits and video watch time; those numbers are estimates and describe content performance. [LinkedIn analytics definitions](https://www.linkedin.com/help/linkedin/answer/a516971/analytics-for-your-posts-articles-and-videos?lang=en)

An initial internal gate is 8 of 10 operators completing one check within ten minutes, with zero incorrect displayed sample calculations and no disclosure confusion. This is a proposed usability gate, not an observed result or an 80% model accuracy claim. Passing ten sample sessions supports the next pilot. It does not establish real document accuracy or readiness for mass acquisition.
